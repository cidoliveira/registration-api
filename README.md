REST API for managing people and tasks, built with Java and Spring Boot. It supports creating, listing, updating, and
deleting both resources, with persistence through Spring Data JPA and H2. Made with educational purposes.

Each person can be associated with one task, and a task can have multiple people assigned to it.

## Technology

- Java 17
- Spring Boot 4.1.1
- Spring Web MVC and Spring Data JPA
- H2 Database
- Flyway
- Lombok
- Maven Wrapper

## Running locally

Install JDK 17 and configure `JAVA_HOME`. Run the following commands from the project root. The included Maven Wrapper
downloads Maven and dependencies on first use.

### Windows (PowerShell)

```powershell
$env:DATABASE_URL = 'jdbc:h2:mem:cadastro;DB_CLOSE_DELAY=-1'
$env:DATABASE_USERNAME = '<your-database-username>'
$env:DATABASE_PASSWORD = '<your-database-password>'

.\mvnw.cmd spring-boot:run
```

### Linux and macOS

```sh
export DATABASE_URL='jdbc:h2:mem:cadastro;DB_CLOSE_DELAY=-1'
export DATABASE_USERNAME='<your-database-username>'
export DATABASE_PASSWORD='<your-database-password>'

sh ./mvnw spring-boot:run
```

The default base URL is `http://localhost:8080`. Check the application with `GET /persons/hello`.

Replace `<your-database-username>` and `<your-database-password>` with the credentials you want to use for the new
in-memory H2 database.
For an existing database, supply its actual
username and password. Data in this in-memory database is discarded when the application stops.

Flyway applies V1 to create the tables and their relationship, then V2 to add the profession column.
Hibernate validates the resulting schema through `ddl-auto=validate`.

## Configuration

Settings are defined in [`application.properties`](src/main/resources/application.properties).

| Environment variable | Purpose                | Local example                            |
|----------------------|------------------------|------------------------------------------|
| `DATABASE_URL`       | H2 JDBC connection URL | `jdbc:h2:mem:cadastro;DB_CLOSE_DELAY=-1` |
| `DATABASE_USERNAME`  | Database username      | `<your-database-username>`               |
| `DATABASE_PASSWORD`  | Database password      | `<your-database-password>`               |

The configured JDBC driver is H2. The H2 console is available at `http://localhost:8080/h2-console`; connect using the
same JDBC URL and credentials as the application.

## Endpoints

Request bodies use JSON. IDs are generated by the database.

### People

| Method   | Path                       | Action                  |
|----------|----------------------------|-------------------------|
| `GET`    | `/persons/hello`           | Return a greeting       |
| `POST`   | `/persons/create`          | Create a person         |
| `GET`    | `/persons/getall`          | List all people         |
| `GET`    | `/persons/getperson/{id}`  | Retrieve a person       |
| `PUT`    | `/persons/changedata/{id}` | Replace a person's data |
| `DELETE` | `/persons/delete/{id}`     | Delete a person         |

Example body for `POST /persons/create`:

```json
{
  "personName": "Ana Oliveira",
  "personEmail": "ana@example.com",
  "personAge": 30,
  "personProfession": "Developer",
  "userTasks": null
}
```

To associate a person with an existing task, set `userTasks` to an object containing its ID, for example
`{"taskId": 1}`. The association is stored on the person. Email addresses have a database uniqueness constraint.

### Tasks

| Method   | Path                     | Action                |
|----------|--------------------------|-----------------------|
| `POST`   | `/tasks/create`          | Create a task         |
| `GET`    | `/tasks/getall`          | List all tasks        |
| `GET`    | `/tasks/gettask/{id}`    | Retrieve a task       |
| `PUT`    | `/tasks/changedata/{id}` | Replace a task's data |
| `DELETE` | `/tasks/delete/{id}`     | Delete a task         |

Example body for `POST /tasks/create`:

```json
{
  "taskName": "Review registration records",
  "taskDifficulty": "Medium"
}
```

`taskDifficulty` is a string; the code does not define a fixed set of accepted values. Task responses include an
`assignedPersons` field.

### Response behavior

- Creation returns `201 Created` with a text message containing the generated ID.
- List and single-resource reads return `200 OK` with JSON.
- Successful updates and deletions return `200 OK` with a text message.
- Reads, updates, and deletions by ID return `404 Not Found` with a text message when the resource does not exist.

Updates map the submitted body to a replacement entity; send all fields you intend to retain. Before deleting a task,
remove or change its associations with people, since the relationship has no cascade removal configured.

## Docker

With Docker installed, build the image from the project root:

```sh
docker build -t api-cadastro .
```

Run it from a shell where the database environment variables above are set:

```sh
docker run --rm -p 8080:8080 -e DATABASE_URL -e DATABASE_USERNAME -e DATABASE_PASSWORD api-cadastro
```

The Dockerfile builds the application with Maven and Java 17, then runs it on a Java 17 JRE.
The image build skips tests; run the test command separately. The in-memory database is discarded when the container
stops.

## Tests and build

With the environment variables above set in the same shell:

| Action              | Windows (PowerShell)       | Linux / macOS             |
|---------------------|----------------------------|---------------------------|
| Run tests           | `.\mvnw.cmd test`          | `sh ./mvnw test`          |
| Build and run tests | `.\mvnw.cmd clean package` | `sh ./mvnw clean package` |

The packaged application is written to `target/api_cadastro-0.0.1-SNAPSHOT.jar` and can be started with:

```sh
java -jar target/api_cadastro-0.0.1-SNAPSHOT.jar
```

The current test suite contains an application-context loading test. It does not cover individual endpoints or service
behavior.

## Project structure

```text
src/main/
  java/com/cidoliveira/api_cadastro/
    RegistrationApplication.java
    Persons/                       Person controller, service, repository, DTO, mapper, and entity
    Tasks/                         Task controller, service, repository, DTO, mapper, and entity
  resources/
    application.properties
    db.migrations/                 Flyway SQL migrations
src/test/                          Application-context test
```

Controllers handle HTTP requests, services coordinate operations, repositories access the database, and mappers convert
between entities and DTOs.
